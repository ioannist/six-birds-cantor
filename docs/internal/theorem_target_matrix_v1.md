## Primary class
`safe_finite_memory_local_subclass`

## Stretch class
`quasi_multiplicative_local_cantor_class`

The reason is straightforward. Current repo evidence strongly supports a theorem program on bounded-memory / finite-state / simple local-domain families: baselines are calibrated, prefix-memory behavior is stable enough to trust as a proof target, and at least one genuine local-domain family is already implemented. The broader quasi-multiplicative local class is the right stretch target because it preserves the non-SFT ambition without forcing the project to prove the whole vision at once. The tempered-memory class is still too far ahead of the current mathematical and computational evidence.
